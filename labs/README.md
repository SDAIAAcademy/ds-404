## The case and its data

Every lab works on **Bustan Food Wholesale**, a fictional food wholesaler. All data in `data/` is synthetic, generated by `prepare_data.py` with the seed 404 (`uv run python prepare_data.py` rewrites it identically):

| File | What it holds | Days |
|---|---|---|
| `orders.csv.gz` | 80,000 orders: customer, depot, region, segment, distance, lines, cases, truck utilisation, driver tenure, holiday flags, delivery hours, late flag | 1, 4 |
| `demand.npz`, `series_meta.csv` | 400 daily series (100 products at four depots) from 19 July 2023 to 15 June 2026 | 2, 3 |
| `calendar.csv` | one row per day with its Hijri holiday state (pre-Ramadan, Ramadan, pre-Eid, Eid) | 2, 3 |
| `products.csv`, `trucks.json` | product costs, prices, shelf life, case volume and weight; truck, reefer and depot capacity (synthetic rates) | 3 |
| `leaderboard_claim.csv` | a vendor's benchmark table of 36 datasets | 1 |
| `adoption/` | candidate licences (checked November 2026), Bustan's classification register, a cost sheet | 4 |
| `reference/` | supplied results: backtests, zero-shot forecasts and every lab's reference result | all |

Every lab starts from these supplied files and needs no other lab to have run.

## Pretrained models: Colab or the stand-in

- **In Google Colab**, the first cell installs `requirements-colab.txt`. Install `tabicl` or `chronos-forecasting` in the runtime to let the real models answer; their weights download into Colab, never to your laptop.
- **Everywhere else**, `bustan.py` uses a labelled stand-in: for tables a spline logistic regression averaged with nearest neighbours, for series a weekday profile with holiday multipliers learned from the context. They are not pretrained models. Every printed result names who answered.
- The supplied reference results were written by the stand-ins. A cohort that runs the real models should read its own numbers aloud and compare.

## Quick mode

`BUSTAN_QUICK=1` makes every lab smaller (fewer rows, series, repeats and configurations) so that it runs in a few minutes on a slow laptop or a free Colab CPU. Results differ from the reference in the third decimal or more; the checks still pass.

## Windows

- Long paths: run `git config core.longpaths true` in the repository once.
- Keep the uv environment outside a deeply nested folder: `set UV_PROJECT_ENVIRONMENT=C:\uv404` (cmd) or `$env:UV_PROJECT_ENVIRONMENT="C:/uv404"` (PowerShell) before `uv sync`.
- The Day 4 labs fit LightGBM with one thread: on one Windows test machine four threads were about thirty times slower, with identical results.
